## 0. 为什么不是「一个 .gyroflow 就够」

我们原来只让用户选一个 `.gyroflow` 文件。它其实是**用户在 Gyroflow 里「挑一个镜头标定 + 改点稳定化参数」
后保存出来的快照**，因此：

- 换一台相机（不同传感器/镜头/分辨率）→ 里面的 `calibration_data` 完全不适用；
- 但 `.gyroflow` 里手调过的**稳定化参数**（fov / max_zoom / adaptive zoom / 平滑参数 / 地平线锁定…）
  是通用的、值得保留的。

所以终态是**两件事分开**：

| 概念 | 设置字段 | 来源 | 选中后的语义 |
|---|---|---|---|
| 预设 | `gyro.preset_file_path`（`.gyroflow`） | 我们自己的预设目录（`presets/` 等） | 整份应用：标定 + 稳定化参数 |
| 镜头标定 | `gyro.lens_profile`（库 key 或 `.json` 路径） | Gyroflow 镜头库（12409 条）+ 用户 `.json` | **只覆盖标定**，其余参数继续用预设 |

两者都可在同一个搜索框里搜到；界面下方两行分别显示当前生效的「预设」「镜头标定」，各带 ✕ 清除。

## 1. 镜头库从哪来（原版 Gyroflow 的四层来源）

1. **自带的标定数据库** `profiles.cbor.gz`：gzip 压的 CBOR 数组，元素是 `[文件名, 标定 JSON]`。
   它**不在源码仓库里**（`gyroflow-src/.gitignore` 忽略 `resources/camera_presets`），由
   `gyroflow-src/src/core/build.rs` 在**编译时**发现缺失就从
   `https://github.com/gyroflow/lens_profiles/releases/latest/download/profiles.cbor.gz` 下载 ——
   真正的数据源是独立仓库 **gyroflow/lens_profiles**。
   发行版把它放在 exe 同级的 `camera_presets/`；移动端/`bundle-lens-profiles` 用 `include_bytes!` 编进二进制。
   本仓库那份（2026-08-27 下的）：1 514 864 B → 解开 8.9 MB，顶层数组 **9811 项**（含 `__version`=41）。
2. **用户数据目录**：`settings::data_dir()`（Windows = `%LOCALAPPDATA%\Gyroflow\lens_profiles`）里的
   `.json` / `.gyroflow` / 更新下来的 `profiles.cbor.gz`；非空时优先加载。
3. **运行时从 GitHub 更新**：`fetch_profiles_from_github()` 比对 release tag 与库里的 `__version`，
   新则覆盖（bundle 路径可写就写那里，否则写用户目录）。关掉：在 `camera_presets/` 里放空文件 `noupdate`。
4. **显式选入**：搜索框（原版是 SearchField + Open file 按钮）/ 拖放 / CLI。

`load_all()` 之后 `prepare_list_for_ui()` 把每条展开成 UI 列表项（`compatible_settings` 会让一个标定文件
变成多条：不同分辨率/宽高比/数码镜头）。**实测加载后 12409 条**。

## 2. 本项目的实现

### 2.1 `app/src/lens_db.rs`

- **发现**：在候选位置找 `profiles.cbor.gz` —— 开发时的 `gyroflow-src/resources/camera_presets/`、
  `./camera_presets/`、`./resources/camera_presets/`、`./presets/camera_presets/`、exe 同级的同名目录、
  `%LOCALAPPDATA%|%APPDATA%\Gyroflow\lens_profiles\`、`%APPDATA%\TraceReel\presets\camera_presets\`。
- **落地**：`LensProfileDatabase::get_path()` 只认 cwd/exe 同级的 `resources/camera_presets`、`camera_presets`、
  `lens_profiles`（且只看**目录是否存在**）。所以 `ensure_db_visible()` 把找到的库**复制**到它认的目录
  （dev 下是 `target/debug/camera_presets/`，发布版是 exe 同级 `camera_presets/`），已存在就跳过。
  → 想换库，直接替换这个目录里的 `profiles.cbor.gz` 即可。
- **进程级单例**：`shared()` 用 `OnceLock<Arc<RwLock<LensProfileDatabase>>>`，整库只解析一次
  （**实测 1.36 s 解析 + 0.20 s 建列表**）；`warmup()` 在 GUI 启动时丢到后台线程，避免第一次输入卡顿；
  `is_ready()` 供 UI 显示「镜头库加载中…」。
  `gyro::load_stabilizer` 也把这个 Arc 装进新的 `StabilizationManager`（该字段是 pub），
  所以**每段视频不再重复解析**（原来是每段都 `load_all()`）。
- **搜索** `search(query, limit)`：合并两个来源 → JSON
  `{ready, total, db, dir, items:[{kind:"preset"|"lens", id, name, note}]}`：
  1. 我们自己的预设目录（`presets::scan_files()`，含 `.gyroflow`/`.json`）—— 排在前面（同 Gyroflow 的优先级）；
  2. 镜头库：直接用 `LensProfileDatabase::search()`（**空格分隔的每个词都要命中**，内置 `gopro11`→`hero11 black`
     之类的别名归一），按「收藏/预设 → 画幅匹配 → 名称」排序，最多 200 条，我们再截到 `limit`。
- **解析成标定 JSON** `resolve_lens_json(id)`：`id` 是文件路径就直接读（`.gyroflow` 取 `calibration_data`），
  否则按库 key `get_by_id()` / `find()` 取 `LensProfile::get_json()`。

### 2.2 应用（`app/src/gyro.rs`）

`load_stabilizer(video, gyro: &GyroSettings, …)` —— **设置页是唯一真源**：

1. `apply_preset_calibration()`：只从 `.gyroflow` 取 `calibration_data`（→ 镜头标定）和
   `output.interpolation`（插值方式）。预设里的 `stabilization` 段**不再**直接生效；
2. 若 `gyro.lens_profile` 非空 → `resolve_lens_json()` → 写临时 `.json` → `stab.load_lens_profile(tmp)`
   **覆盖**预设里的标定；顺带应用标定自带的 `frame_readout_time` / `frame_readout_direction`；
3. `apply_gyro_settings(&stab, gyro)`：把设置页里那一整套参数逐项应用 ——
   fov、变焦方式/速度/上限/迭代/中心、镜头校正、地平线锁定(+roll/重力向量)、
   帧读出时间/方向、视频速度+三个联动开关、附加 3D 旋转/平移、
   平滑方式与该方式的参数（`smoothing_params` JSON，逐项 `set_parameter`）；
4. 之后照旧 offset → autosync(默认关) → `recompute_smoothness/adaptive_zoom/undistortion`。

**选中 `.gyroflow` 时**：QML 调 `settings.preset_fields(path)`（Rust 用
`GyroSettings::apply_preset_json` 解析预设的 `stabilization` 段）→ 把返回值逐个写进设置页
→ 再 `applyChange("gyro_preset")` 重建稳定化器。所以「选预设 = 把它那套参数填进面板，之后随便改」。

### 2.2.1 「稳定化」设置页（对应原版 Stabilization 面板）

`app/src/bin/gui.qml` 的「视频」页里有一组 **稳定化（改完点「应用稳定化设置」）**，字段与
`.gyroflow` 的 `stabilization` 段一一对应：

| 分组 | 控件 | 设置字段 |
|---|---|---|
| 平滑 | 平滑方式 + 该方式的参数滑杆（**动态**取自 `smoothing_params()`，中文标签） | `gyro_smoothing_method` / `gyro_smoothing_params` |
| 变焦 | 变焦方式 / 变焦速度(秒) / 变焦上限(%) / 迭代次数 / 中心 左右,上下 | `gyro_zoom_mode` / `gyro_zoom_window` / `max_zoom` / `max_zoom_iterations` / `gyro_zoom_center_x,y` |
| 视野/镜头 | 视野 / 镜头校正量 | `fov` / `gyro_lens` |
| 地平线 | 锁定(%) / 横滚修正(°) / 使用重力向量 | `gyro_horizon` / `gyro_horizon_roll` / `gyro_use_gravity` |
| 卷帘 | 帧读出时间(毫秒) / 方向 | `frame_readout_time` / `gyro_readout_dir` |
| 速度 | 视频速度(%) / 联动平滑 / 联动变焦 / 联动变焦上限 | `gyro_video_speed` / `gyro_vs_*` |
| 附加 | 附加旋转 偏航/俯仰/横滚 / 附加平移 左右/上下/前后 | `gyro_rot_*` / `gyro_tr_*` |
| 同步 | 陀螺偏移(毫秒) / 偏移(帧) | `gyro_offset` / `gyro_offset_frames` |

数值项一律用 `SliderField`（滑杆 + 数值框，对应原版 `SliderWithField`）；只有「变焦迭代次数」「陀螺偏移帧数」
是纯整数框（`ISpin`）。预设文件改回上面的 `Field` 文本输入框（可手输/浏览）。

⚠️ **控件立即生效**（对齐原版：改完就重算）：滑杆用 `live: false`，一次拖动只在**松手**时写一次值。

### 2.2.2 「改参数不重载」：硬输入 / 参数 两条路（重要）
**踩过的坑**：一开始 QML 把任何 `gyro_*` 属性变化都当成「需要重载防抖」→ 调
`item.apply_settings(p, true)` → 那是**整份工程重来**（重探测视频、重载地图/路线/解码器、**重读运动数据**、
时间轴归零）。用户反馈「为什么一改就要重新加载、重新读运动数据」就是这个。修正后分成两条路：

| 变化 | 走哪条 | 代价 |
|---|---|---|
| `video_path`（真的换视频） | `apply_settings(p, true)` 完整重来 | 重探测 + 重载地图 + 重读运动数据 |
| `gyro_preset` / `gyro_lens_profile` / `gyro_enabled`（视频没变） | `apply_gyro_params` → **只重建稳定化器**（`gyro-only reload`） | 重读运动数据，但不动地图/路线/解码器/播放位置 |
| 其余稳定化参数（视野/变焦/平滑/地平线/卷帘/速度/旋转平移/偏移） | `apply_gyro_params` → **只重算**，且按参数分级 | 见下 |

Rust 侧：`hard_gyro_sig(settings)` = 视频段 + 预设 + 镜头标定 + 开关；只有它变了才算硬输入。
`gui.rs::apply_gyro_params(path, prop)` 判定后调用 `gyro::reapply_settings(snapshot, gyro, offset, prop)`，
后者**只应用被改的那一个字段**（`apply_gyro_field`）—— 全部字段重设会让没变的字段也
`invalidate_smoothing/zooming`，白白重算上百万帧。

**分级重算**（依据 gyroflow_core 各 setter 自己 invalidate 什么）：

| 改的属性 | 重算什么 | 实测（debug，142 万四元数/23 分钟） |
|---|---|---|
| `fov`、`frame_readout_time`、`gyro_readout_dir` | 只刷新每帧参数（`recompute_undistortion`） | **0.00 s** |
| `gyro_lens`、`gyro_zoom_*`、`max_zoom*`、`gyro_tr_*` | + `recompute_adaptive_zoom` | ≈20 s |
| 平滑方式/参数、地平线、视频速度、附加旋转、陀螺偏移 | + `recompute_smoothness` | ≈50 s |

（debug 构建无优化；release 会快一个数量级。原版 Gyroflow 拖滑杆同样要重算平滑/变焦，只是它是 release 且把重算放在线程里。）

**重算在后台线程**（`start_recompute`/`poll_recompute`，`item.tick()` 里收尾）：长视频重算要几秒~几十秒，
放 GUI 线程会冻住界面。期间状态栏显示「防抖: 正在重算参数…（不重读运动数据）」+ busy 遮罩；
连续拖动会**合并**成一次（`recompute_pending` 只留最新的一份），结束后自动请求新帧重绘。

### 2.2.3 滑杆组件的两个坑（会「拖了没反应」/ 报绑定循环）

```qml
// SliderField：不要写 `value: 绑定`，也不要用 onMoved
Slider { id: sfSlider; live: false; onValueChanged: sf.store(value) }
Connections { target: win; function onRefreshTickChanged() { sf.sliderSync() } }  // 命令式同步
```
1. **`onMoved` 不可靠**：`live: false` 时松手才写值，有的 Qt 版本此时不再发 `moved()` ——
   只挂 `onMoved` 就会「拖了没反应」（用户实测）。改用 `onValueChanged`，并在 `store()` 里
   加「值没变就 return」的守卫（同时挡住程序化回写）。
2. **不要给 `value` 写绑定**：绑定读 `settings[prop]`、`onValueChanged` 又写回它，Qt 会报
   `Binding loop detected for property value`（`store()` 里同步调 `refreshFields()` 同样会触发）。
   正确做法是命令式同步：`sliderSync()` 在 `refreshTick` 变化时把滑杆位置设过去。
3. **初始化时滑杆会把 `value` 夹到 `from`**（最坑的一个）：`Slider` 一建立就把 `value` 夹进 `[from,to]`，
   于是 `onValueChanged` 在 `Component.onCompleted` **之前**就会用最小值触发一次；处理函数若直接写回，
   设置就被改成 `from`。表现就是「平滑参数那几个滑杆动不了 / 值全变成 0.001」（`from: 0.001`），
   而且因为发生在 Repeater 建委托的过程中，还会把**只填了几行的半个列表**写回设置（8 → 12 → 16 条地增长）。
   修法：委托加 `property bool ready: false`，`Component.onCompleted: { sliderSync(); ready = true }`，
   处理函数里 `if (!ready || syncing) return`；`SmoothParams` 另加 `reloading` 重入保护，
   重建列表期间 `writeBack()` 直接返回，重建自身走 `writeRaw()`。
   同样的坑 `SliderField` 也有（`from: -1000` 的附加平移会被写成 -1000），已一并加 `ready` 守卫。


**滑杆范围对齐原版**（`range` 与 `scale` 都在 QML 里；`scale` 用于「显示单位 ≠ 存储单位」）：

| 控件 | 范围 | 单位 | 存储（`scale`） |
|---|---|---|---|
| 视野 | 0.1–3 | — | 比率 |
| 变焦速度 | 0–15 | 秒 | 秒 |
| 变焦上限 | 110–300 | % | 百分数 |
| 变焦中心 左右/上下 | −100–100 | % | ÷100（−1..1） |
| 镜头校正量 / 地平线锁定 | 0–100 | % | ÷100 |
| 地平线横滚修正 / 附加旋转 | −180–180 | ° | 度 |
| 帧读出时间 | 0–100 | 毫秒 | 毫秒 |
| 视频速度 | 10–1000 | % | ÷100（1.0 = 原速） |
| 附加平移 | −1000–1000 | 像素 | 像素 |
| 陀螺偏移 | −1000–1000 | 毫秒 | 毫秒 |

界面标签一律中文（`Pitch/Yaw/Roll` → 俯仰/偏航/横滚；`FOV` → 视野；`ms` → 毫秒）；
平滑方式与平滑参数的中文名在 QML 里映射（Rust 只给英文 `description`）：
不平滑 / 默认 / 平面三维 / 固定机位；参数如 `smoothness` → 平滑度、`alpha_0_1s` → 响应系数（0.1 秒）。

**平滑参数为什么是动态的**：`SettingsProxy::smoothing_methods()` 返回算法名列表
（No smoothing / Default / Plain 3D / Fixed camera），`smoothing_params()` 返回当前算法的参数定义 + 当前值
（`SmoothingAlgorithm::get_parameters_json()`，含 name/description/from/to/value/default）。
QML 用 Repeater 生成滑杆；改动写回 `gyro_smoothing_params`（JSON）并立即应用。
**坑**：`writeBack()` 里**绝不能**再调 `refreshFields()` —— 会 refreshTick → 重建滑杆 → `value: model.val`
绑定重新初始化 → `onMoved` → 写回 …… 无限递归（实测直接把 QML 栈打爆，报
`RangeError: Maximum call stack size exceeded`）。滑杆只用 `onMoved`，不要用 `onValueChanged`；
参数写回走 `applyChange`（防抖），不直接 `refreshFields`。


### 2.3 QML（`app/src/bin/gui.qml`）

- `component ProfileSearch`：`TextField`（`placeholderText: "搜索..."`）+ 180ms 防抖 + `Popup`/`ListView` 结果
  （↑↓ 选择、回车确认、Esc 关闭）+ 当前「预设」「镜头标定」两行（带 ✕ 清除）+ 库状态提示行
  （加载中 / `镜头库 12409 条 · <路径>` / 未找到时提示放文件的目录）。

- `SettingsProxy::search_profiles(text, limit)` / `profiles_warmup()` 是 QML 入口。

### 2.4 设置持久化（`.orv`）

`[gyro]` 新增两键：`lensProfile`（库 key / `.json` 路径）、`lensProfileName`（显示名）。
**故意不做相对路径解析**：库 key 常常长得像路径（如 `Sony/Sony_A7sIII_….json`），
按 .orv 目录 join 会把它毁掉。

## 3. 拖放导入（预览区）

`DropArea` 铺在预览区（`anchors.fill: previewArea`，声明在 `item`/`HudCanvas` 之后 = 最上层；
它不处理鼠标事件，因此不影响预览/HUD 编辑）。按扩展名映射：

| 拖入 | 落到的设置 | 效果 |
|---|---|---|
| `.orv` | — | `loadProject()` 打开工程 |
| 视频（mp4/mov/mkv/avi/m4v/mts/m2ts/insv/mpg/mpeg/webm/wmv） | `video_path` / `video_extras` | **第一个 = 主视频；之后再拖 = 追加续接分段**（不替换主文件） |
| 图片（jpg/jpeg/png/bmp/tif/tiff/webp） | `route_path`+`map_path` / `map_extras`+`map_change_times` | **第一个 = 主图**（同一个文件既是底图也是轨迹来源，QuickRoute JPEG 自带轨迹）；之后再拖 = 追加额外地图，换图时间留空（沿用上一项，可在「轨迹」页改） |
| `.gpx` | `hud_gpx_path` | HUD 轨迹 |
| `.gyroflow` | `gyro_preset` | 防抖预设（整份：标定 + 把 stabilization 段填进「稳定化」页） |
| `.json` | `gyro_lens_profile` | 镜头标定 |

拖动经过时预览区显示蓝色蒙层提示；每个文件都会写日志窗口（`WARN 不认识的文件类型` 兜底）。

## 4. 目录约定（放文件即可生效，不用改代码）

| 想放什么 | 放哪儿 |
|---|---|
| `.gyroflow` 预设 | 仓库根的 `presets/`（开发）/ `<exe>/presets` / `%APPDATA%\TraceReel\presets` |
| 镜头库 `profiles.cbor.gz` | `<exe>/camera_presets/`（或任意候选位置，启动时会自动搬到这儿） |

QML 是运行时从磁盘读的，改界面不用重编译；`lens_db.rs`/`presets.rs` 改动需要 `cargo build`。
